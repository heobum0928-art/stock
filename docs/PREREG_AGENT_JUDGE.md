## 0. 가설 (사용자 제안)
"몇 가지 종목만 놓고 에이전트(LLM)에게 직전 10~15분 정보를 주고 방향을 추론시키면 어떤가.
한 종목에 여러 에이전트를 붙여도 된다. 매매는 봇이 한다."

### 이미 알려진 것 — 먼저 적어둔다

  → 종목 우주는 사람이 고르지 않고 **기계적으로** 정한다.

  미로그인. 그래서 **"수집 먼저, 판단은 나중에 일괄"** 구조로 설계한다.
- **사전 기대치: 엣지 0.** 60분 지평에서 왕복 수수료 0.10%(명목)를 이겨야 한다.

## 1. 데이터 — 스냅샷 (미래 누출 차단)
스냅샷 시각 t = 신호 발생 시각. 입력은 **t 이전 정보만**, 결과는 t 이후 정보만.

| 구분 | 내용 |
|---|---|
| 출처 | 그림자함대 신호(`shadow_signals.csv`) + 실거래 진입 시각(원장 2종). 7h 급등 15~40% 신호 = 기계적 우주 |
| 입력 | 직전 15개 1분봉(OHLCV), 직전 60분 요약, 24h 등락·거래대금, 펀딩레이트, BTC 직전 15분 |
| 결과 | t+15 / t+30 / **t+60분** 종가 수익률(명목 %). 판정 지평은 **60분 하나**로 고정 |
| 비용 | 왕복 수수료 0.10% 명목. 60분 내 펀딩 정산이 걸리면 실측 반영 |
| 호가창 | 과거분은 복원 불가. 소급 스냅샷엔 없음, 전방 수집분엔 포함(별도 열). 판정은 호가창 없는 버전으로 통일 |

소급 생성분(과거 신호 ~200건)과 전방 수집분(가동 후 신호)을 **같은 형식**으로 쌓는다.

## 2. 에이전트 (지금 고정)
같은 스냅샷을 받고 `{"direction": "long"|"short"|"skip", "confidence": 1~10}`만 낸다.
- A1 모멘텀 해석자 / A2 역추세 해석자 / A3 위험 심판(둘의 의견을 받아 최종) / **E 앙상블**(A1·A2·A3 다수결, 불일치 시 skip)
- 모델·프롬프트는 `research/agent_judge/agents.py`에 고정. 결과를 본 뒤 프롬프트를 고치면 새 에이전트(A4…)로 등록하고 재판정 대상에서 뺀다.
- 응답은 스냅샷별로 캐시(jsonl). 같은 스냅샷에 두 번 묻지 않는다.

## 3. 대조군
- **C1 기계규칙**: 항상 short (현행 숏봇의 결정과 동일 방향)
- **C2 동전**: 시드 20260905 무작위 long/short
- 짝비교 대상은 **같은 스냅샷**. 그룹 평균 비교 금지(CLAUDE.md 3항).

## 4. 판정 기준 — 지금 고정, 결과 보고 수정 금지
지표: 판단한 스냅샷의 **60분 순수익률(명목 %, 수수료·펀딩 반영) 평균**. skip은 0이 아니라 **제외**하되 skip률을 별도 기록.

각 에이전트(A1·A2·A3·E)가 **전부** 충족해야 채택 후보:
| # | 기준 | 조건 |
|---|---|---|
| C1 | 판단(비skip) 표본 | **≥ 100건** (미달이면 "표본 미달 → 보류") |
| C2 | 순수익률 평균 | **> 0** |
| C3 | C1 기계규칙 대비 짝차이, 일-블록 부트스트랩 4000회(시드 20260905) 95% CI 하한 | **> 0** |
| C4 | C2 동전 대비 짝차이 95% CI 하한 | **> 0** |
| C5 | 다중검정: 에이전트 4개 동시 → **BH-FDR q=0.10** 통과 |
| C6 | 홀드아웃 `md5(sym)%4==0`(탐색 때 안 봄)에서 **C2·C3 부호 동일**. 한 번만 연다 |
| C7 | 최대기여 단일 날짜 제외 시 C2 부호 유지 |

### 즉시 기각
- skip률 > 80% (옛 봇의 실패 모드 재현) → "판단 안 함"으로 기록, 종료
- C2 ≤ 0

### 통과해도
**실거래 아님.** 실거래 전환은 사용자가 결정한다(CLAUDE.md 6항). 실거래로 가려면 별도로
청산 규칙(손절)·동시노출·LLM 지연/장애 시 동작을 사전등록해야 한다.
