# 사전등록 — 동시 보유 상한 (concurrency cap)

**작성 2026-09-18. 손익 계산을 한 건도 하기 전에 작성했다. 작성 후 수정하지 않는다.**
(작성 전 본 것: 동시 보유 개수의 **시간 분포만**. 상한별 성적은 보지 않았다.)

---

## 0. 왜

오늘 두 검정이 모두 "개별 거래를 손봐서는 안 된다"를 가리켰다:
- 시장 폭 가드(`PREREG_BREADTH_GUARD.md`) → 표본 부족, 판정 보류
- 손절선 40/30/25(`PREREG_STOP_LEVEL.md`) → **판별 불가**, 40% 유지

남은 구조적 사실: **손실 -80%p 이상 17건이 156건이 번 이익의 절반을 먹는다.**
그리고 2026-09-13~17 손실은 한 종목이 아니라 **여러 종목이 같은 날 동시에** 물려서 났다.

동시 보유 상한은 `docs/CAPITAL_LADDER.md`에 **2026-08-19부터 "미구현"으로 적혀 있던 항목**이다.
새 아이디어가 아니라 밀린 숙제다.

**실측한 구조**(성적 아님): 최대 동시 보유 **11개**. 시간 비중 0개 9.4% / 1개 26.6% / 2개 17.4% /
3개 16.9% / 4개 12.9% / 5개 8.9% / 6개 이상 8.0%.

## 1. 표본 — 지금 고정

- `data/margin_short_ledger.csv` + `data/margin_short_wide_ledger.csv` 청산 완료 숏 거래.
- 제외: `net_pnl_pct_margin < -100`(기존 이상치 규칙).
- 두 봇을 **한 계좌로 합쳐서** 본다(실제로 한 계좌를 쓰므로).

## 2. 반사실 규칙 — 지금 고정

거래를 **진입 시각 순서대로** 재생한다. 상한 K일 때:

- 진입 시점에 이미 보유 중인 포지션이 **K개면 그 진입은 건너뛴다**(선착순, 대기열 없음).
- 건너뛴 거래는 없었던 것으로 본다. 그 거래의 손익·증거금 점유 모두 발생하지 않는다.
- 보유 중 판단은 원 거래의 **진입~청산 시각**을 그대로 쓴다. 상한이 다른 거래의 청산 시각을
  바꾸지는 않는다(청산 규칙은 건드리지 않는다).
- 각 거래의 손익은 **원 거래의 `net_pnl_pct_margin`을 그대로** 쓴다(증거금 기준 %).

**자본 잣대 — 전 조건 동일하게 고정.** 건당 증거금 M = 100(단위 무관, 비율만 본다),
계좌 자본 **C = 5 × M**로 모든 상한에 동일 적용한다. 상한이 낮다고 자본을 줄이지 않는다
(그러면 상한을 유리하게 만드는 셈이다).

## 3. 통계량 — 지금 고정

**기간 총손익 ÷ C** = 계좌 수익률 %. 건당 평균이 아니다 — 상한은 거래 수를 바꾸므로
건당 평균으로 비교하면 안 된다.

- 부트스트랩: **7일 날짜블록(진입일 기준) 4,000회, 시드 20260918**.
  각 재추출마다 **블록 안에서 상한 규칙을 다시 재생**한다(동시성이 블록 내에서 보존되도록).
  블록별 계좌 수익률의 평균을 통계량으로 쓴다.
- MDE(양측 95%·검정력 80%) 병기.

## 4. 판정 — 지금 고정, 결과 보고 수정 금지

**주 비교는 K=3 하나다.** 시간 비중상 3개 이하가 70%를 덮어 "대부분의 시간은 그대로 두고
과밀 구간만 자르는" 값이기 때문이며, 성적을 보고 고른 값이 아니다.
**K=2, K=5는 강건성 병기이며 주 판정으로 승격하지 않는다**(CLAUDE.md 5항).

통계량 = **(K=3 계좌 수익률) − (상한 없음 계좌 수익률)**, %p.

| # | 조건 | 판정 |
|---|---|---|
| C1 | 점추정 > 0 **그리고** 95% CI 하한 > 0 | **동시 보유 상한 효과 확인** |
| C2 | 점추정 > 0, CI 0 포함, \|점추정\| ≥ MDE | 유망 — 전방 재확인 |
| C3 | \|점추정\| < MDE | **판별 불가** |
| C4 | 점추정 < 0 | **기각** — 상한 두지 않는 게 낫다 |
| C5 | 상한 없음 조건의 거래 수 < 100 | 표본 부족, 판정 보류 |

## 5. 필수 병기 (판정에 쓰지 않음)

- 상한별: 체결된 거래 수 / 건너뛴 거래 수, 계좌 수익률, **최대 낙폭(MDD)**, 최악 단일일 손익
- 건너뛴 거래들만의 평균 손익 — **거른 게 실제로 나쁜 거래였나**(핵심 진단)
- 자본 회전율(평균 동시 보유 개수)
- 엔진별(원본/완화) 건너뛴 비중
- 최대기여 단일 날짜 비중

## 6. 금지

- K를 2/3/5 외로 늘려가며 좋은 값 찾기. 건당 평균으로 비교하기.
- 상한이 낮은 조건에만 자본 C를 줄여 수익률을 부풀리기.
- 결과를 보고 이 문서 수정. 정정은 `docs/would_change_log.md`에 append.

## 7. 통과해도

**실거래 자동 반영 없음.** 동시 보유 상한은 진입을 막는 설정이다. 결과를 보고하고,
봇 코드 변경은 **사용자가 직접 결정**한다(CLAUDE.md 6항).
