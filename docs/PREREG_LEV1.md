# 사전등록 — 레버리지 1배 + 손절 -80%(명목) 검증

**작성일 2026-08-24. 결과를 보기 전에 작성했다.**
**실행일: 51건 관문 통과 이후.** 관문 전에는 돌리지 않는다.

---

## 0. 왜 관문 이후인가

51건 관문은 통계적 목표가 아니라 **반응적 과최적화를 막는 행동 훈련 장치**다
(`CLAUDE.md` 7항). 관문 직전에 새 백테스트를 돌려 "관문 끝나면 이걸로 바꾸자"는
답을 미리 만들어두면 장치의 취지가 무너진다. 사용자 제안으로 연기했다.

**기준만 지금 확정한다.** 계산은 나중에 하되, 통과선은 결과를 보기 전에 고정한다.

---

## 1. 가설 (하나만)

> 레버리지를 2배 → 1배로 낮추고 손절선을 역행 -40% → -80%(명목)로 옮기면
> **증거금 대비 건당 기대값이 개선된다.**

### 근거 (2026-08-24 (5) 분석)
2배에서는 강제청산이 역행 **42.86%**에 있고 손절선이 **40%**다 — **여유가 2.86%p뿐**이다.
-40%에 닿은 572건 중 **532건(93.0%)이 그대로 강제청산까지 갔다.** 기다릴 공간이 없다.

한편 회복은 실제로 일어난다:

| 최대 역행 | 최종 플러스 비율 |
|---|---|
| ~10% | 89.6% |
| ~20% | 64.4% |
| ~30% | 69.6% |
| ~35% | 62.6% |
| 40%+ | 23.6% |

1배로 낮추면 강제청산선이 **역행 90.48%**로 멀어진다. 같은 증거금 손실(-80%)을
감수하면서 **가격이 움직일 공간이 2배**가 된다.

⚠️ 이건 "손절선 조정"(후보 3, 기각)과 **다른 것**이다. 후보 3은 2배를 유지한 채
손절선만 -20/-25/-30으로 **당겼다**. 여기는 레버리지를 낮춰 **공간 자체를 늘린다**.
강제청산 위치가 바뀌므로 단순 비례 축소가 아니다.

## 2. 비교 설정 (정확히 두 개, 이것만)

| | A (대조·현행) | B (제안) |
|---|---|---|
| 레버리지 | 2.0배 | **1.0배** |
| 손절 (명목 역행) | 40% | **80%** |
| 손절 (증거금 기준) | -80% | **-80%** (동일) |
| 강제청산 (명목 역행) | 42.86% | **90.48%** |
| 트레일링 | 트리거 명목 +15%, 반납 10%p | **동일** |
| 만기 | 48h | 동일 |
| 증거금 | 50 USDT | 동일 |

**손절 시 증거금 손실을 -80%로 맞춰 "건당 위험"을 동일하게 뒀다.** 바뀌는 것은
가격이 움직일 수 있는 공간뿐이다.

- 진입 규칙: 현행 동결 규칙 그대로 (7h 수익률 30~40%, 24h 거래대금 ≥300만, 12h 쿨다운,

- 청산 손실은 -100%로 캡
- 봉내 순서: optimistic / pessimistic 둘 다 산출, **판정은 optimistic**(기존 관행 동일)
- 짝비교: 같은 signal_id에서 A와 B의 차이를 취한다 (`CLAUDE.md` 3항 — 그룹평균 금지)

## 4. 통과 기준 (결과 보기 전 확정 — 이후 수정 금지)

### 1차 관문 — "개선인가"
아래 **네 가지를 전부** 충족해야 개선으로 인정한다.

1. 짝차이 평균 **(B − A) > 0**
2. 종목 클러스터 부트스트랩 4,000회 **95% CI가 0을 포함하지 않음**
3. **홀드아웃**(md5(sym)%4==0, 약 603건)에서도 **부호 동일**
4. **2025-10-11 제외** 시에도 **부호 동일**

> 3·4는 이 프로젝트에서 후보 5·6·7·8·9가 죽은 두 가지 방식(홀드아웃 미확인,
> 단일 날짜 의존)을 그대로 막는 조건이다.

### 2차 관문 — "전략이 살아나는가"
B 자체의 건당 기대값이 **> 0** 이고 부트스트랩 95% CI가 0을 제외.

**1차만 통과하면 "덜 나쁨"이고 전략 존속 근거가 아니다.** 판정문에 그대로 쓴다.

### 병기 필수
슬롯 5개 제약 하 **월간 손익**을 같이 낸다. 1배는 같은 증거금으로 노출이 절반이라
건당 EV가 좋아져도 자본 대비 총수익은 다를 수 있다.

## 5. 다중검정 — 설정을 늘리면 이 사전등록은 무효다

**검정하는 설정은 B 하나뿐이다.** 따라서 보정하지 않는다.

- 0.5배·1.5배·3배 등 **다른 레버리지를 이어서 시험하지 않는다.**
- 손절선을 -70%/-90% 등으로 **미세조정하지 않는다.**
- 트레일링 파라미터를 **같이 건드리지 않는다.**

위 중 하나라도 하면 이 문서는 무효이고, 전체를 다중검정 보정 대상으로 다시 설계해야 한다.
(`CLAUDE.md` 5항 — 여러 기준을 대보고 통과하는 걸 고르지 않는다.)

## 6. 미리 밝히는 편향 — **B에 유리하다**

2026-08-24 (4)에서 확인: 그림자함대 최악 건이 **-108%**였다. 손절은 증거금 -80%에서
걸려야 하는데 -108까지 밀렸다. **실제 스탑 슬리피지가 백테스트 가정(-81.4%)보다 나쁘다.**

B는 스탑 발동 빈도가 낮으므로 **이 편향의 피해를 덜 본다 → B가 실제보다 좋게 나온다.**
1차 관문을 통과해도 이 점을 판정문에 반드시 병기한다.

또한 백테스트 전반의 봉내 체결가 불확실성(-0.55% ~ -2.36% 밴드, 미해결)이 그대로 남는다.

## 7. 실패 시 행동

**후보 종료.** 다른 레버리지 값이나 손절선으로 이어가지 않는다.
"이 방향은 가능성이 있는데 파라미터만 다르면" 류의 후속 제안을 하지 않는다.

## 8. 통과 시에도 — 실거래 적용은 별도 결정

백테스트 통과는 **실거래 변경 승인이 아니다.**

1. 51건 관문 판정이 먼저 끝나 있어야 한다
2. 레버리지 변경은 실제 돈이 나가는 설정 변경이므로 **사용자가 직접 한다**
   (`CLAUDE.md` 6항). AI는 `armed_engines`·캡·레버리지를 임의로 바꾸지 않는다
3. 적용 전 그림자함대에 변형으로 먼저 태우는 것을 권한다 — 백테스트만 보고
   실거래를 바꾼 전례가 이 프로젝트에 좋게 끝난 적이 없다
