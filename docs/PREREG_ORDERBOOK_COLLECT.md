## 0. 왜 수집부터인가

호가창 스냅샷은 **과거를 살 수 없다.** 지금 안 모으면 영원히 없다.
따라서 "검정할 가치가 있는가"를 먼저 따지지 않고, **싸게 모아두는 것**이 이 단계의 목적이다.

근거: 호가창 불균형(order-flow imbalance)은 학술 문헌이 두껍다(arXiv 2506.05764 등).
다만 이 저장소는 같은 계열인 **고래발자국(1,946건, -0.47%, CI 0 배제)**과 **OFI**를 이미 기각했다.
**따라서 사전확률은 낮게 잡는다.** 이 수집은 "될 것 같아서"가 아니라 "비용이 전기값뿐이라서" 한다.

또한 원래 계획이던 **강제청산 스트림은 수집 불가**로 확인됐다 —
2026-09-16 실측: `fstream.binance.com`(선물 웹소켓)이 이 회선에서 차단됨.
현물 웹소켓·선물 REST는 정상. 그래서 **REST 폴링으로 가능한 호가창만** 모은다.

## 1. 수집 사양 — 지금 고정, 변경 금지

| 항목 | 값 | 이유 |
|---|---|---|
| 엔드포인트 | `/fapi/v1/depth`, `limit=20` | 가중치 2. 20단계면 벽 형태를 보기 충분 |
| 주기 | **5초** | 분당 12회×종목수. 10종목이면 분당 240(한도 2,400의 10%) |
| 대상 종목 | **고정 6개 + 동적 4개** | 아래 §2 |
| 저장 | `data/ob/ob_YYYY-MM-DD.csv` (일 단위) | 하루 약 10만 행 예상 |
| 보관 | 무기한(용량 문제 시 압축) | 디스크 773GB 여유 확인 |

**저장 컬럼 (지금 고정)**
```
ts_ms, symbol, mid, spread_bp,
bid_usdt_20, ask_usdt_20,        # 상위 20단계 누적 명목가
imb_20,                          # (bid-ask)/(bid+ask), -1~+1
bid_usdt_5, ask_usdt_5, imb_5,   # 상위 5단계(가까운 벽)
best_bid, best_ask, best_bid_qty, best_ask_qty
```
`imb`가 +면 매수벽이 두껍다는 뜻이다. **파생 지표는 저장하지 않는다** — 원자료만 남기고
가공은 분석 시점에 한다(나중에 정의를 바꿀 수 있도록).

## 2. 종목 선정 — 지금 고정

- **고정 6개**: BTCUSDT, ETHUSDT, SOLUSDT, XRPUSDT, DOGEUSDT, BNBUSDT
  (유동성 상위, 시장 기준선 역할. 고래발자국이 BTC에서 실패했으므로 대조군으로도 쓴다)
- **동적 4개**: 1시간마다 갱신. 24h 거래대금 300만 USDT 이상 중
  **7시간 급등률 상위 4종목** — 즉 **봇이 실제로 진입하는 종류의 코인**.
  기존 기각(고래발자국)은 대형코인 위주였다. 이 저장소의 우위가 나온 자리는 급등 알트다.

**동적 종목이 바뀌어도 과거 기록은 지우지 않는다.**

## 3. 이 단계에서 하지 않는 것

- **신호 생성·매매 판단 없음.** 순수 수집이다.
- **판정 기준을 지금 정하지 않는다**(맨 위 참조).
- 수집 중 중간 분석 결과를 보고 사양(주기·종목·컬럼)을 바꾸지 않는다.
  바꿔야 할 이유가 생기면 `would_change_log.md`에 적고, **새 수집 트랙을 따로 연다**
  (같은 트랙 안에서 사양이 바뀌면 표본이 오염된다).

## 4. 최소 수집 기간 — 지금 고정

**2026-12-16까지 3개월, 또는 급등 신호 진입 100건이 커버될 때까지** 중 나중에 오는 쪽.
그 전에는 판정 문서를 쓰지 않는다. 중간에 "될 것 같다/안 될 것 같다"는 말도 하지 않는다.
