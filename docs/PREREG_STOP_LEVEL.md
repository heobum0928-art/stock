# 사전등록 — 손절선 재검정 (명목 40% vs 30% vs 25%)

**작성 2026-09-18. 손익 계산을 한 건도 하기 전에 작성했다. 작성 후 수정하지 않는다.**
(작성 전 본 것: 건수, 청산사유 분포, 손실 구간 도수. 대안 손절선의 성적은 보지 않았다.)

## 0. 왜

실거래 173건에서 **손실 -80%p 이상 17건이 -1,421%p**를 차지한다. 나머지 156건이 번 +2,789%p의
절반이다. 이 17건은 **손절 실패가 아니라 설계대로 작동한 결과**다 — 손절선 40%는 명목가 기준이고
레버리지 2배라 증거금 기준 -80%다(CLAUDE.md 2항).

2026-08-22에 `V5_stop30`을 짝비교했을 때 기존 40% 대비 **+5.27%p 우위**였으나 표본 부족으로
판정 보류였다. 그때 48건, 지금 173건이다. **새 아이디어가 아니라 보류된 판정의 재개다.**

## 1. 표본 — 지금 고정

- `data/margin_short_ledger.csv` + `data/margin_short_wide_ledger.csv` 청산 완료 숏 거래.
- 제외: `net_pnl_pct_margin < -100`(기존 이상치 규칙), 5분봉 경로 재현 실패 건.
- 잣대: **증거금 기준 %** (= 명목 기준 × 2).

## 2. 반사실 계산 규칙 — 지금 고정

각 거래의 진입~청산 구간 5분봉(고가/저가)을 조회해 경로를 재현한다.

- **진입가**: 진입 시각이 속한 5분봉의 종가를 근사로 쓴다(실체결가 미기록 건이 있으므로 전 건 동일 규칙).
- 손절선 S(명목 %)에 대해, 역행이 처음 S에 닿는 봉을 찾는다. 숏이므로 **고가 ≥ 진입가 × (1+S/100)**.
- 닿으면 **그 가격에 청산**한 것으로 본다. 슬리피지는 명목 **0.05%** 추가 불리하게(엔진 `STOP_EXTRA`).
  수수료는 원 거래와 동일하게 진입·청산 1회씩 `FEE_SIDE` 0.06%(명목).
- 닿지 않으면 **원 거래의 실제 손익을 그대로 쓴다**(같은 청산가·시각).
- 펀딩: 조기 청산 시 보유기간이 줄지만, 펀딩은 원 거래 값을 **그대로 둔다**(보수적 — 숏은 펀딩을
  대체로 수취하므로 조기 청산에 유리하게 잡히지 않게 하려면 줄여야 하나, 8h 단위 재현 오차가 커서
  그 대신 전 조건에 동일 값을 써 **짝차이에서 상쇄**시킨다).
- **기존 40%도 같은 방식으로 재현한다.** 실제 손익과 직접 비교하지 않는다 —
  재현 오차가 조건 간 상쇄되도록 **재현값끼리** 비교한다. 40% 재현값 vs 실제값의 괴리는 병기한다.

## 3. 판정 — 지금 고정, 결과 보고 수정 금지

통계량: **짝차이(대안 − 40% 재현), 건당 증거금 기준 %p**.
부트스트랩: **7일 날짜블록(진입일 기준) 4,000회, 시드 20260918**. MDE(양측 95%·검정력 80%) 병기.

**주 비교는 30% 하나다.** 25%는 강건성 병기이며 **주 판정으로 승격하지 않는다**
(여러 값을 대보고 통과하는 걸 고르는 것을 금지 — CLAUDE.md 5항).

| # | 조건 | 판정 |
|---|---|---|
| S1 | 30%의 짝차이 평균 > 0 **그리고** 95% CI 하한 > 0 | **손절 30% 우위 확인** |
| S2 | 점추정 > 0, CI 0 포함, \|점추정\| ≥ MDE | 유망 — 전방 재확인 |
| S3 | \|점추정\| < MDE | **판별 불가** |
| S4 | 점추정 < 0 | **기각** — 40% 유지 |
| S5 | 재현 성공 건수 < 100 | 표본 부족, 판정 보류 |

## 4. 필수 병기 (판정에 쓰지 않음)

- 40% 재현값 평균 vs 실제 평균의 괴리(재현 품질 검증 — 괴리 > 3%p면 **판정 자체를 무효**로 본다)
- 조건별: 평균·중앙값·승률·최악 5건 평균·최대손실
- **손절선을 조여서 망친 건수**(40%에선 이익인데 30%에선 손절) vs **구한 건수**
- 엔진별(원본/완화) 분리, 최대기여 단일 날짜 비중
- 25% 강건성 결과

## 5. 금지

- 30%/25% 외의 값을 추가로 대보고 좋은 걸 고르기.
- 결과를 보고 이 문서 수정. 정정은 `docs/would_change_log.md`에 append.
