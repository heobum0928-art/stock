# 사전등록 — 고래 대량체결이 이후 가격을 예측하는가

**작성 2026-09-18. 계산을 한 건도 하기 전에 작성했다. 작성 후 수정하지 않는다.**
(작성 전 본 것: 파일 행 수·컬럼명·첫 행뿐. 수익률은 계산하지 않았다.)

---

## 0. 왜

실거래 173건으로는 **건당 10%p 미만의 개선이 보이지 않는다**(2026-09-18 실측: 건당 표준편차
39.9%p). 오늘 네 검정이 모두 "판별 불가"로 끝난 진짜 이유다.

`data/whale_print_events.csv`는 **245,314행**(2026-07-06~)이다. 질문을 "내 거래가 벌었나"에서
**"이 신호 뒤에 가격이 움직였나"**로 바꾸면 표본이 173 → 24만이 된다. 수집만 하고
**한 번도 판정에 쓴 적이 없는 데이터**다(6월부터 축적).

## 1. 큰 표본의 함정 — 먼저 못 박는다

24만 건이면 **경제적으로 무의미한 0.01% 차이도 "통계적으로 유의"하게 나온다.**
그래서 **유의성을 판정 기준으로 쓰지 않는다.**

**판정 기준은 크기다: 왕복 비용 0.12%(명목, `FEE_SIDE` 0.06% × 2)를 넘는가.**
유의성은 "그 크기가 우연이 아닌가"를 확인하는 **보조**로만 쓴다.

## 2. 데이터·지표 — 지금 고정

- `data/whale_print_events.csv`: `time, coin, side(bid/ask), size_krw, ratio_to_median,
  price, val_24h_eok, range_pos_2h`.
- **미래 가격은 같은 파일 안에서 구한다**(외부 API 호출 금지 — 오늘 레이트리밋으로
  호가창 수집기를 멈추게 한 사고가 있었다). 기준 이벤트 이후 같은 코인의 이벤트 중
  **경과시간이 목표 구간 H 이상이면서 가장 이른 것**의 `price`를 미래 가격으로 쓴다.
- **경과시간이 2H를 넘으면 그 건은 버린다**(측정 지연이 큰 건 제외).
- 수익률 = `(미래가 / 기준가 − 1) × 100`, **명목 기준 %**.

## 3. 검정 — 지금 고정

**주 구간 H = 1시간.** 하나다. 5분·15분·4시간은 병기하되 **주 판정으로 승격하지 않는다**
(CLAUDE.md 5항).

통계량 = **(bid 프린트 평균 수익률) − (ask 프린트 평균 수익률)**, %p.
bid = 고래 매수 체결, ask = 고래 매도 체결. "고래가 사면 오르나"의 직접 측정이다.

부트스트랩: **7일 날짜블록 4,000회, 시드 20260918**. (코인·시각이 겹치므로 iid 가정 금지.)

| # | 조건 | 판정 |
|---|---|---|
| W1 | \|차이\| **≥ 0.24%p**(비용의 2배) **그리고** 95% CI가 0을 포함하지 않음 | **쓸 만한 신호** |
| W2 | \|차이\| ≥ 0.12%p(비용) 이상 0.24%p 미만, CI가 0 제외 | 존재하나 **비용 대비 얇음** |
| W3 | \|차이\| < 0.12%p | **쓸 수 없음** — 유의해도 비용을 못 넘는다 |
| W4 | CI가 0을 포함 | **판별 불가** |
| W5 | 매칭 성공 건수 < 10,000 | 표본 부족, 판정 보류 |

**부호가 반대로 나와도(고래가 사면 내린다) W1을 적용한다.** 그 경우도 쓸 수 있는 신호다.

## 4. 필수 병기 (판정에 쓰지 않음)

- bid/ask 각각의 건수·평균·중앙값, 매칭 실패율, 평균 경과시간
- **크기별 구간**(`ratio_to_median` 4분위)별 차이 — 큰 프린트일수록 강한가
- **코인별 쏠림**: 상위 1개 코인이 표본의 몇 %인가, BTC 제외 시 결과
- 5분·15분·4시간 병기
- `range_pos_2h`(2시간 레인지 내 위치) 상·하단별 차이

## 5. 금지

- 구간·크기 구간·코인 필터를 바꿔가며 통과하는 조합 찾기.
- **유의성(p값·CI)만으로 "신호가 있다"고 말하기.** 크기가 비용을 넘지 못하면 없는 것이다.
- 외부 API로 미래 가격 보강하기(수집기 보호).
- 결과를 보고 이 문서 수정. 정정은 `docs/would_change_log.md`에 append.

## 6. 통과해도

**주문 로직 아님.** 통과 시 다음 단계는 이 신호를 쓰는 **모의 전략 사전등록**이며,
실거래 반영은 사용자가 직접 결정한다(CLAUDE.md 6항).
