# 연구 실적 기준 (사용자 결정 2026-10-21)

**연구가 수익으로 증명되지 않으면 규모를 줄인다.** 결과를 보고 이 기준을 바꾸지 않는다.

## 1. 합격선 (한 줄)
- **기준 시각:** 2026-10-21 12:24 KST (`data/loss_stop_baseline.json`의 시각, 선물 지갑 1,174.7 USDT).
- **판정일:** 2026-12-31.
- **합격:** 기준 시각 이후 선물 계좌 순손익(실현손익 + 수수료 + 펀딩, 입출금 제외)의 합계가 **0 이상**이면 연구를 지금 규모로 계속한다.
- **불합격:** 합계가 0 미만이면 연구 루틴을 주 1회 이하로 줄이거나 중단한다(최종 결정은 사용자).
- **중지선과의 관계:** 순손익이 -100 USDT에 닿으면 새 숏 진입을 자동으로 막는다(`scripts/loss_stop_watch.py`). 판정일 전에 이 선에 닿아도 판정일의 합계 기준은 그대로다.

## 2. 월별 손익표
- 매월 1일(또는 사용자가 "손익표"라고 할 때) `scripts/monthly_pnl.py`로 월별 순손익을 만든다.
- 롱(BTC·ETH·SOL 심볼)과 숏(그 외 심볼)을 나눠 보고, 실현손익과 평가손익을 따로 적는다.
- 숫자는 항상 USDT, 거래소 income 내역 기준이다. 모의 수익은 실적으로 치지 않는다.

## 3. 새 전략의 승급 경로
1. 사전등록 → 과거 데이터 시험 → 독립 기간(또는 전방) 재검증 → 체결 가능성 확인.
2. 모두 통과하면 **승급 제안서**를 사용자에게 올린다. 상한은 **50 USDT**부터, 전략별 손실 한도 -25 USDT를 같이 제안한다.
3. 실거래를 켜는 것(`armed_engines`, 캡, 레버리지)은 사용자가 결정한다. 연구 루틴과 제안서는 설정을 바꾸지 않는다.

## 4. 연구 질문의 조건
- "이 결과가 나오면 **돈을 이렇게 바꾼다**"가 정해진 질문만 한다. 정해진 행동이 없는 연구는 하지 않는다.
- 새 아이디어는 사용자가 가져오는 것을 우선한다. 같은 표본을 쪼개는 방식은 쓰지 않는다.

## 5. 금지
- 판정일·합격선·기준 시각을 결과를 보고 바꾸는 행위.
- 모의 수익이나 "기각 건수"를 실적처럼 보고하는 행위.
