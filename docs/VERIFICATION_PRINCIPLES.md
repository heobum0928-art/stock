# 신규 검증장치(모의봇·필터·로거) 배포 원칙

7개 AI 교차검증 합의(2026-08-17, docs/would_change_log.md 참고). **Case #1**:
bc_rule_shadow_paper.py가 배포 당일 무한 재미러링 버그로 PORTAL 심볼 119회 중복
기록(실거래 영향 없음, 로그 오염만). 이 사례를 계기로 원칙화.

## 원칙 1 — 신뢰 사다리 (Trust Ladder)

새 봇/필터는 아래 단계를 순서대로 거친다. 단계를 건너뛰고 바로 의사결정에 쓰지 않는다.

| Level | 기간/표본 | 역할 |
|---|---|---|
| 0 — 검증중 | 배포~1~2일 | 결과 무시. 로그 직접 읽고 로직만 확인 |
| 1 — 참고용 | 1~2주, <20건 | 결과는 참고만, 주 판단은 다른 근거로 |
| 2 — 의사결정 가능 | 20건+ | 결과 반영하되 사람이 스팟체크 병행 |
| 3 — 자동신뢰 | 50건+ | 자동 판단에 포함 |

## 원칙 2 — 그라운드트루스 대조 (Shadow Mode)

배포 직후 5~10건은, 이미 결과가 난 실전 포지션을 미러링해서 **같은 청산시점·가격을
재현하는지** 확인한다. 재현 실패 = 로직 버그(Case #1이 정확히 이 케이스).

## 원칙 3 — 자기일관성/멱등성 (Idempotency)

배포 전 반드시 확인:
- 같은 입력(같은 심볼+같은 진입시각, 가능하면 거래소 고유 주문/포지션ID)이 두 번
  들어와도 같은 결과가 나오는가?
- "이미 처리한 진입"을 다시 새 진입으로 착각하지 않는 안전장치가 있는가?
- Case #1 원인이 정확히 이 가드 누락이었음 — 새 봇마다 이 항목 명시적으로 체크.

## 원칙 4 — 실패모드 카탈로그

배포 전에 "이게 어떻게 망가질 수 있는가"를 미리 나열:
- 데이터 오염(중복·누락)
- 타임존/시계열 버그
- 부분 실패(상태 파일 갱신은 됐는데 로직은 실패해서 불일치)
- 경쟁 조건(같은 봇 인스턴스 2개 동시 실행)
- 메모리/상태 누적 오류

## 원칙 5 — 카나리 + 롤백

가능하면 소수 심볼/조건에만 먼저 적용 → 이상 없으면 확대. 문제 생기면 즉시 이전
버전으로 되돌릴 수 있게 커밋 단위로 관리(이미 git 커밋마다 하고 있음, 계속 유지).

## 체크리스트 (새 모의봇/필터 만들 때마다)

- [ ] 멱등성 가드 있는가(같은 진입 두 번 처리 안 함)?
- [ ] 배포 후 1~2일은 결과를 의사결정에 안 쓰기로 미리 정했는가?
- [ ] 실전 포지션 상태 변화(청산 등)를 감지하는 로직이 폴링 주기와 안 어긋나는가?
- [ ] 로그만 보고 첫 5~10건이 말이 되는지 사람이 직접 확인했는가?
